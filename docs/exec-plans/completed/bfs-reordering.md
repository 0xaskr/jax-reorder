# 第一轮：基于 BFS 的 jaxpr 计算图规范化与比较

## 目标与完成条件

第一轮只判断计算图是否等价：消除同一计算图中变量编号、独立方程排列产生的差异，保留节点语义、依赖边、操作数位置和运算分组。用输出驱动的 BFS 确定编号，再按依赖深度和 BFS 编号重排方程，不进行交换律、结合律等代数变换。

判断依据是[架构与比较契约](../../../ARCHITECTURE.md)及[两轮规范化与比较结果](../../references/equivalence-results.md)。本计划只实现其中第一轮；2026-10-11 已完成实现、自审与本地验收。设计、原语清单及 review 见 [开发记录](../../design-docs/archive/bfs-reordering.md)。

完成时应满足：

- 全部方程都能从输出回溯到时，改变原始变量编号或合法的方程排列，不改变生成的 BFS 编号与重排后的连接关系。
- 原始算子、参数、常量、抽象值、输入输出顺序、多输出端口及共享关系全部保留。
- 未参与输出的纯计算仍然存在；只要存在未规范化部分，结果就必须标记为部分完成，不能宣称整个 jaxpr 已获得唯一形式。
- 生成的方程列表满足先定义、后使用；这是保留依赖关系后的正确性检查，主要目标仍是结构规范化。
- 以 `jax.lax` 原语在锁定 JAX 版本、CPU 后端的实际支持能力为范围。原语支持的参数、dtype 和 shape 都应支持，不额外限定为少量参数值、dtype 或 shape 白名单。
- 由 AI 生成经典组合及真实模型层的变换前后代码，给出图等价性判断和理由，并生成带具体反例的实际不等价案例。固化为可复现用例，由结构检查与 CPU 执行复核。
- 提供计算图等价、计算图不等价、无法判定三种本轮结果。图不等价不自动升级为数学公式或一般 Python 函数不等价，不实现代数模式。
- 算法应适用于范围内的合法组合；验收使用 AI 构造的经典案例与模型层变体，不再要求穷举所有原语对、参数或任意规模计算图。

## 设计与取舍

### 1. 建立计算依赖图

- 每次 primitive 调用对应一个方程节点，同名或参数相同的调用仍是不同节点。
- 输入和常量是源值；每条使用关系记录生产者的输出端口及消费者的操作数位置。
- 固定函数输入、输出的位置。变量名称和原始方程索引仅用于查找，不能决定输出依赖子图的规范顺序。
- 同一值被多次使用时保留所有使用关系；同一方程产生多个输出时仍只建立一个节点。

### 2. 从输出反向 BFS，生成统一编号

1. 按函数输出顺序注册其生产者，并放入 FIFO 队列。直接返回输入或常量时记录源值，不创建计算节点。
2. 节点第一次入队时分配 BFS 编号；已经入队或处理过的节点直接复用编号。
3. 每次出队后，严格按操作数位置访问输入的生产者，依次注册尚未发现的节点。
4. 保留每个引用的输出端口，不把共享节点展开成重复计算，也不合并内容相同的节点。

顺序由输出位置、操作数位置和连接关系决定，不按算子名字排序。primitive、参数和常量仍属于节点语义，不能因为连接方式相同而忽略它们。

### 3. 按依赖深度分层，统一层内顺序

对于纯数据流图，输入与常量深度为 0。方程深度定义为 `1 + max(输入生产者的深度)`；没有计算前驱的方程深度为 1。原语要求的 token 或其他顺序依赖也必须纳入建图，不能只检查张量边后就重排有顺序约束的节点。

输出依赖子图按 `(依赖深度, BFS 编号)` 排序。同一深度的节点互不依赖，BFS 编号用于确定层内顺序。依赖图相同时，深度也相同，因此原始方程列表中独立节点跨层交错的写法同样可以被归一。

依赖深度不同于到输出的最短距离。对于 `a = sin(x); b = cos(a); c = a + b`，反向 BFS 顺序为 `c, a, b`，但依赖深度依次为 `a:1, b:2, c:3`，重排后必须保持 `a, b, c`。不能直接把 BFS 顺序或其反转当作最终方程顺序。

对不含嵌套图的方程，复用原方程、变量和常量对象，只替换方程列表的顺序。BFS 编号作为独立的结构信息记录，不需要修改变量对象来获得确定性。规范化嵌套图时只重建包含新子图的必要容器，完整保留其余字段，不修改输入 jaxpr。

接口同时返回重排结果、节点编号、深度、值引用映射及未规范化部分。值引用区分输入位置、带完整类型和值的字面量、捕获常量，以及 `(生产者 BFS 编号, 输出端口)`。捕获常量在结构信息中按输出与 BFS 操作数遍历时的首次引用编号，保留原有绑定与共享关系；不修改原 jaxpr 的常量列表，也不按数组打印内容合并常量。没有被访问的常量绑定单独报告。

仅仅得到相同的整数编号序列，不能说明两个图匹配。本轮比较必须同时核对这些引用、primitive、参数与抽象值；打印出的变量名称仍然可能不同。比较使用完整结构，不能仅比较打印文本或摘要。持久化序列化与一般函数级比较接口留待后续。

### 4. 保留未参与输出的分支

从输出 BFS 无法覆盖所有可能存在的方程。对于未访问的纯计算方程，第一版按原有相对顺序追加到输出依赖部分之后，并单独报告这些方程。有 effects 或其他顺序约束的节点不能按这一策略当作普通未使用分支处理。

原 jaxpr 已满足依赖顺序，因此保留这些方程的相对顺序，并把它们使用的输出依赖部分提前，仍能保持依赖合法。不支持的 effects 或不透明参数即使出现在这部分，也必须明确拒绝。

例如 `a+b=c; c+d=e; e+f=g` 加上独立的 `x+y=z`，假设所有源值都是输入、函数只返回 `g`，最长依赖链仍为三层。`z` 所在方程可以保留在末尾；方程的线性位置不代表其依赖深度。若 `z` 也被返回，则按输出位置正常参与 BFS。

这一保留策略不保证未使用分支之间有唯一顺序，不能宣称整个 jaxpr 已获得唯一规范形式。此类输入的验收要求是完整保留、依赖合法并报告部分完成，不能要求任意打乱未使用分支后仍得到相同的全图顺序。后续比较必须覆盖保留部分；无法完成完整结构比较时返回无法判定，不能只比较输出依赖部分。

### 5. 第一轮支持边界

- 以锁定环境中的 JAX 0.11.2 与 CPU 后端为实现和验证基线。GPU、TPU 不在当前范围内；CPU 原语需要的轴环境、设备配置等执行上下文应随用例记录。
- 从 `jax.lax` 及其公开子模块建立原语清单，核对包装函数追踪后实际出现的 primitive。支持单位是原语，不是人工挑选的某个 `(原语, 参数, dtype, shape)` 样例。
- 对范围内原语，凡 JAX 在相应 CPU 环境支持的合法参数、dtype 和 shape，均属于目标支持范围。完整保存并比较这些信息，不擅自转换 dtype、改变 shape 或改写参数来通过比较。
- 合法性与 CPU 支持能力依据锁定版本的原语规则和后端实现判断。JAX 自身拒绝的调用属于无效输入或 CPU 不支持；JAX 能处理而本项目尚不能处理的调用属于实现缺口，不能改称不在范围内。
- 清单记录原语的实现进度、参数处理方式和用例覆盖，不作为缩小合法参数、dtype、shape 范围的白名单。有限测试样本只是验证证据，不定义支持上限。
- `cond`、`while`、`scan` 等包含子图的 CPU 原语也需处理。保留外层调用、分支顺序、循环携带值、捕获值和参数，在各嵌套图内部按同一结构规则规范化；不做内联、循环展开或跨区域搬移。
- JAX 包装 API 产生的调用节点也要显式处理。例如本次 MLP 示例中的 `jax.nn.silu` 追踪出了 `jit` 节点；不能忽略或删除它来获得匹配。
- 对 token、effects 和其他顺序约束，按原语语义建立依赖或保持必要顺序；不把 `effects` 为空视为可随意重排的充分依据。尚未处理的 effects、子图或不透明参数明确报告无法判定并登记缺口，包括它们出现在未使用分支的情况。
- 有效输入须满足 SSA 与依赖约束；悬空引用、重复定义和环明确失败。参数比较必须覆盖全部语义字段，不能通过忽略未知字段获得匹配。
- 保留重复计算和未使用计算；不进行公共子表达式合并、死代码删除、常量折叠或调用内联。
- 本轮不生成或执行交换律、结合律、分配律等代数规范化规则；只比较给定输入输出接口下的计算图。

JAX 的方程以 primitive、参数和有序值引用表示；公开函数名与实际 primitive 不能直接视为一一对应，清单应以锁定版本的追踪结果核对。参见 [jaxpr 语言](https://docs.jax.dev/en/latest/601/jaxpr.html)和 [jax.lax API](https://docs.jax.dev/en/latest/jax.lax.html)。实现与逐项验证见 [CPU 清单](../../references/lax-coverage.md)；测试样本不限制原语合法域。

### 6. 预期复杂度

对单个图，设方程数为 V，使用及顺序依赖关系数为 E。BFS 和深度计算为 O(V+E)，排序为 O(V log V)，总空间为 O(V+E)。嵌套图的编号与排序成本分别计算再合计；JAX 递归类型检查、顺序根扫描、参数和常量的精确比较成本另计，不能把大数组内容比较当作常数时间。使用迭代遍历，避免长链触发 Python 递归深度限制。

### 7. 任意合法组合的正确性依据

在输出依赖部分，对保留输入位置、输出位置、操作数位置、结果端口及节点语义的一一对应图，按以下步骤论证：

1. 输出根的入队顺序相同；每次展开对应节点时，有序前驱与已访问关系相同，因此 BFS 编号相同。共享节点只编号一次，不依赖原方程位置。
2. 源值深度相同，沿依赖关系归纳可得对应节点深度相同，因此 `(深度, BFS 编号)` 给出相同顺序。
3. 每条计算依赖边都从较小深度指向较大深度；重排只置换方程对象，不改变任何定义、使用、参数或常量绑定。
4. 对纯算子，输入值及算子语义不变，按依赖关系归纳可得重排保留图的计算。嵌套图按各自边界递归应用；token 与 effects 需另行验证其顺序约束，不能直接套用纯数据流结论。未使用部分另外检查保留与依赖合法，不纳入唯一顺序承诺。

这份论证不依赖 `sin`、`cos` 等具体算子名称，也不限制组合长度。AI 构造的用例用于发现编号、端口、参数比较和重排的错误，不把案例通过数量当成一般正确性证明。

### 8. 本轮比较结果

| 结果 | 条件 |
| --- | --- |
| 计算图等价 | 全部节点、依赖、端口、语义字段及嵌套结构完成比较，仅有变量编号或允许的独立方程排列差异 |
| 计算图不等价 | 完整图比较中存在确定的结构或语义字段差异，报告具体位置；不由此推断公式不等价 |
| 无法判定 | 遇到尚未实现的原语处理、未规范化分支或无法完整解释的语义信息，报告原因 |

AI 为用例给出的“等价”也采用上述图等价含义。若另称某个负例在计算结果上实际不等价，必须给出有效输入和两边不同的输出作为证据。

## 验证用例与验收

### AI 生成与判断流程

1. 选择基准：经典原语组合或 `sglang-jax` 支持模型的一层，固定源码、输入输出接口、参数和 CPU 环境。
2. AI 给出变换前后代码。正例只做变量重命名、独立计算换序或保持相同追踪图的代码整理；负例改变运算、参数、数据来源、连接、结果端口或输出顺序。两边均应是合法可运行代码，语法错误不作为不等价负例。
3. AI 在查看待测比较器结果之前给出 `计算图等价 / 计算图不等价 / 无法判定` 标签与理由。正例列出节点对应关系，负例指出首个结构差异；声称实际计算不等价的案例还需给出反例输入和预期输出。
4. 追踪实际 jaxpr，检查 AI 的变换描述与图相符，并在 CPU 复现实际不等价反例。AI 误标的案例先修正或标为待定，不能把其答案不经核对直接作为真值。
5. 固化代码、输入、标签、理由和证据，再运行本项目规范化与比较。比较器结果应符合已复核的预期；遇到分歧检查双方证据，不以比较器输出反向改写预期标签。

每个用例保存来源与版本、基准和候选代码、变换说明、输入签名与静态参数、AI 判断与理由、实际追踪原语、数值反例或辅助执行记录。采用随机输入时固定种子。AI 在开发阶段生成并判断，CI 重放这些固定用例。

### 经典组合与原语覆盖

| 基准类别 | 图等价变换 | 图不等价变换 |
| --- | --- | --- |
| 多支逐元素计算后汇合 | 交换独立分支的定义顺序，保留汇合的操作数位置 | 将 `mul` 改成 `add`，或让汇合读错分支 |
| 点积、广播与偏置 | 将独立的点积和偏置广播换序 | 改变偏置值、收缩维度或权重来源 |
| reshape、transpose、slice、concatenate | 重排各独立分支，保留所有参数与连接 | 修改切片范围、维度排列或拼接输入顺序 |
| 归约与归一化 | 重排与归约无依赖的旁支，保持归约表达式 | 改变归约轴或归一化常量 |
| 比较、选择与索引 | 重排独立条件和数据准备 | 改变比较原语、选择分支或索引来源 |
| 排序及多输出计算 | 调整独立消费分支的先后顺序 | 引用错误的结果端口，或交换函数输出位置 |
| 共享前驱、菱形与跨层交错 | 改变独立节点的线性排列，保持共享关系 | 将一条边接到另一个节点或改变共享关系 |
| 条件、循环及调用子图 | 在同一子图内重排独立计算，保留外层接口 | 改变条件、循环携带值、子图内容或调用参数 |

上表是 AI 构造经典案例的起点，不是原语白名单。逐项检查 CPU 原语清单，为模型层和经典组合尚未覆盖的原语补充用例，包含无输入、多输出、变长操作数和必要的顺序约束。参数、dtype、shape 从原语合法域中选取有区分度的代表值与边界值；需要 X64 时单独固定配置并检查实际追踪 dtype。测试采样范围不限制功能支持范围。

不再把所有原语对的笛卡尔积、小图穷举或全组合生成器作为必需验收项。新增用例优先覆盖缺失原语、未覆盖语义分支和已发现错误。

下面保留计划阶段的简化 CPU 示例，用于说明变换与判断。正式验收已改用保留 `LinearBase` 精度与分片规则的纯函数提取，完整来源、配置与固定代码见 [模型层记录](validation/bfs-cases.md)：

```python
import jax


def base(x, w_gate, w_up, w_down):
    gate = x @ w_gate
    up = x @ w_up
    activated = jax.nn.silu(gate)
    hidden = up * activated
    return hidden @ w_down


def reordered(x, w_gate, w_up, w_down):
    up = x @ w_up
    gate = x @ w_gate
    activated = jax.nn.silu(gate)
    hidden = up * activated
    return hidden @ w_down


def wrong(x, w_gate, w_up, w_down):
    gate = x @ w_gate
    up = x @ w_up
    activated = jax.nn.silu(gate)
    hidden = up + activated
    return hidden @ w_down
```

- AI 判断 `base` 与 `reordered` 计算图等价：仅交换两个独立投影的定义顺序，所有权重来源、SiLU 输入、乘法操作数位置和最终输出保持不变。
- AI 判断 `base` 与 `wrong` 计算图不等价：同一位置的 `mul` 被替换成 `add`。还存在实际计算不等价反例：四个输入均为 `float32` 的 `(1, 1)` 数组，依次为 `[[1]]`、`[[0]]`、`[[2]]`、`[[1]]`，两者输出分别为 `[[0]]` 和 `[[2]]`。

正式模型层用例已完成 CPU 追踪、数值反例与图比较；另用输入 `(2, 3)`、中间维度 4 和随机种子 17 验证非平凡形状。AI 的判断在调用比较器前保存，程序按固定预期复核。

### 每个有效用例必须检查的性质

1. 对每张输入图，规范化前后方程一一对应，定义与有序使用关系不变；primitive、参数、抽象值、语义上下文、常量绑定及嵌套语义完整保留。
2. 对 AI 标记并已复核的图等价正例，规范化表示一致；对图不等价负例，能指出结构或语义字段差异，不误报等价。
3. 重排结果依赖合法且幂等；检查长链、共享、多输出及未使用分支。存在尚未规范化部分时准确报告，不能只比较输出依赖部分后宣称全图等价。
4. 在固定 CPU 环境复现实际不等价反例，并辅助比较原图和重排图的执行结果。数值相同不替代结构检查；AI 的理由与反例也不能由待测比较器自身生成。

### 必留的结构反例

下表是需要长期保留的算法回归场景，与 AI 生成的经典案例、模型层变体共同验收。

| 用例 | 预期 |
| --- | --- |
| `sin(x)`、`cos(y)` 的书写顺序互换，最后均返回 `a+b` | BFS 编号和重排后的连接关系一致 |
| 同名算子，甚至相同输入的重复调用，原始排列不同 | 按使用位置确定对应关系，不按名字排序或合并节点 |
| `a=sin(x); b=cos(a); c=a+b` | 保持依赖顺序，不直接使用 BFS 或反转 BFS |
| 同一节点同时通过短路径和长路径被输出引用 | 只编号一次，深度取最长前驱路径 |
| `a+a` 与两次独立计算后相加 | 保留共享关系差异；同一生产者被使用两次不能漏边 |
| 多个函数输出、一个方程的多个输出端口 | 保留输出位置和端口编号；方程只入队一次 |
| 三层链加未参与输出的独立分支 | 保留全部方程，最长依赖链仍为三层，报告保留部分 |
| 输入直接返回、常量直接返回、空输出 | 不制造额外计算；输入接口及剩余方程仍保留 |
| dtype、shape、常量或 primitive 参数变化 | 原有语义信息完整保留，不用打印摘要替代比较 |
| 已实现的嵌套计算与顺序约束 | 完整保留和比较，不跨区域重排或忽略顺序依赖 |
| 尚未实现的 effects、子图或不透明参数处理 | 明确报告缺口，包含未参与输出的相关方程，不误报等价 |
| 捕获数组常量的发现顺序变化；同值不同绑定；字面量与捕获常量 | 按引用关系记录常量，保留绑定和共享信息，不依赖打印值或原始槽位判断对应 |
| 无输入的计算节点、变长操作数、只使用部分结果端口 | 正确处理节点深度、每个使用位置及所有结果定义 |
| 悬空引用、重复定义或循环依赖 | 明确报告非法图，不继续排序或死循环 |
| 超过通常递归深度的计算链 | 迭代遍历成功，依赖不变 |
