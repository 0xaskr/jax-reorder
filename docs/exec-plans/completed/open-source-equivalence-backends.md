# 开源数学等价后端的并行评估

状态：2026-10-15 首轮评估完成并归档。成果见[综合报告](../../development-docs/open-source-equivalence-backends.md)，生产集成及完整 layer 证明未包含在已完成范围中。

## 目标与完成条件

用户在 2026-10-15 明确：仓库面向任意两份可追踪的 JAX 程序，区分计算图等价、数学等价、数学不等价及工具无法判断的 unknown。当前计算图比较已有方法，瓶颈是数学等价。真实模型 layer 及其手写改写是验证比较器的输入；验证对象是带算子语义的模型拓扑与数学表达，不是运行模型后的数值相似度。

本任务先记录计划，再由多个 subagent 并行调查、运行符号探针和核对源码，评估社区已有方案是否能复用。允许转换 IR，后端语言不限 Python。此处“任意”是入口目标，不把任何候选描述为能完备判定所有程序；未支持语义、转换失败、预算不足及未完成证明必须明确保留。

完成条件：

- 建立按技术路线分类的候选清单；覆盖主流符号代数、等式饱和、张量重写验证、SMT 和编译器等价工具。
- 每个候选都有官方来源、用途、语义范围、复用内容、接入成本、证据等级和具体适配结论。
- 对优先候选实际运行小型符号证明/反例探针；没有运行的项目明确记为源码评估或环境受阻，不冒充通过。
- 使用共同的数学用例及真实 GLM jaxpr 算子清单评价能力，不能只演示无关的标量恒等式。
- 独立检查假设、负例和 unknown 分类；规则来源必须区分上游已有与本次手写。
- 给出有证据的优先顺序与最小后续接入范围，不在本轮直接替换生产比较器。

## 需求与判定边界

- 计算图等价：沿用仓库当前结构比较能力。
- 数学等价：在明示的数学语义和输入约束下，证明两图的输出表达式一致。
- 数学不等价：有证据证明不是同一计算函数；不要求每一个输入都产生不同输出。结构不匹配或重写未汇合不能代替不等价证据。
- unknown：给出具体原因，包括追踪/转换问题、缺失语义、求解超时和未找到证明；不得统计为负例通过。
- 保留 shape、dtype、常量、索引/归约轴、mask、输入输出绑定及嵌套区域。将张量降为标量时不得丢掉索引和约束。
- 本轮不把 FP32/BF16 误差、运行性能或逐位结果作为验收目标；数学模型的定义域与 `-inf` mask 语义仍需说明。
- 不执行 GLM layer，不做随机抽样，不把优化器输出相似或单次数值一致当作证明。

## 候选范围与并行分工

“所有热门”按路线覆盖，采用可审计清单而不声称穷尽不断变化的开源生态。发现遗漏的直接相关项目时扩充清单。

| 工作线 | 首轮候选 | 负责人 |
| --- | --- | --- |
| 等式饱和与张量规则 | egg、egglog、Tensat、TASO，补查 SPORES、DialEgg | subagent：rewriting |
| 张量证明与约束求解 | TensorRight、Z3、cvc5；Lean/mathlib 作为证明库路线核对 | subagent：verification |
| 计算机代数系统 | SymPy、SymEngine、SageMath、Maxima | subagent：cas |
| 编译器与候选补漏 | MLIR/StableHLO、TVM arith、Alive2、Oryx；Herbie/Daisy 的目标适配性 | 主代理 |

各代理只修改自己的报告与探针目录，不修改生产代码、依赖锁或共用索引。主代理负责索引、统一结果、真实图算子清单和交叉复核。受保护文档保持只读；保留所有已有未提交改动。

## 共同验证集

采用符号表达式、符号索引或抽象 tracing，不分配模型输入。

| 编号 | 用例 | 需要检查的能力 |
| --- | --- | --- |
| E1 | 独立节点的合法换序 | 结构与依赖语义 |
| E2 | `(x+y)*z` 与 `x*z+y*z` | 多步代数改写 |
| E3 | `(Q Kᵀ)s` 与 `(Qs)Kᵀ` | 张量缩放与收缩 |
| E4 | `P V` 与沿 token 的广播乘积求和 | 张量索引与归约等价 |
| E5 | `exp(x+y)` 与 `exp(x)*exp(y)` | 实数函数恒等式及条件 |
| E6 | 带 mask 的 softmax 改写与全 mask 边界 | 条件推理与显式特殊值 |
| N1 | 遗漏缩放 | 数学不等价证据 |
| N2 | 错误归约轴 | 张量负例 |
| N3 | 去掉 ReLU | 分段语义负例 |
| N4 | `< length` 变为 `<= length` | 索引边界负例 |
| N5 | `exp(x+y)` 变为 `exp(x)+exp(y)` | 非多项式负例 |
| U1 | 未支持的算子/控制流或求解资源耗尽 | 明确 unknown，禁止误报不等价 |

每个候选标注实际覆盖哪些用例；不要求为明显不适用的工具建设完整适配器。不能把待证明的等式直接注册为公理后，宣称工具自动证明了该用例。若利用标准张量定义或通用规则，报告规则内容、来源和额外工作量。

真实集为 [GLM 测试脚本](../../../examples/glm52_decode_dsa_mla.py) 中既有的五个正例和五个负例。至少建立原图和改写图的算子/区域覆盖清单，明确小型探针与完整 layer 之间还缺哪些能力。

## 验证结果

- 主代理独立重跑 CAS、SMT、等式饱和脚本；排除时间和具体模型排列后，语义报告与分组原结果一致。
- 真实 QK/PV helper 在 glm 尺寸下直接由 jaxpr 转换，SymPy 索引式分别相同；缺少 QK scale 的均匀符号输入族给出非零多项式证据，仅说明 helper 不等价。
- 抽象 GLM inventory 与 helper 转换均禁用后端编译及 eager 数组运算，未分配模型输入。
- 交叉审查发现实验转换器空输出域误报和常数残差异常，分别增加正大小维度拒绝与精确常数分支；最终七项端到端探针均符合预期。没有将这些实验逻辑接入生产代码。
- 主代理重跑最终端到端脚本，获得三项等价、两项不等价、两项明确 unknown；全程 `compiled=False`、`executed=False`。
- `uv run --no-sync --offline ruff check .`、`ruff format --check .` 全仓通过，161 个 Python 文件格式符合要求。
- `uv run --no-sync --offline python tools/check_docs.py --changed` 与 `git diff --check` 通过；计划归档后再次检查引用。
- 未修改生产代码/项目依赖，未执行 GLM layer，未运行无关全量 pytest，未提交或推送。
