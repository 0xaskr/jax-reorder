# SGLang-JAX 全模型层级对抗验证

## 目标与完成条件

用户要求自主进行对抗测试和 bug 修复，直到 GitHub SGLang-JAX 全部支持模型各选择一个真实 layer，完成 AI 改写比较验证。每个注册架构必须在清单中有来源可核对的层、固定候选及预判、CPU 执行与数值证据；不能用测试跳过、把实际正例标为负例或仅重复同一个通用案例凑覆盖。

## 设计与取舍

- 2026-10-11 通过 GitHub API 核实当前 main 为 `c98ced4a7a64e83261f6672937ce41f0095828ba`（提交时间 2026-10-09）；以此快照注册清单作为本轮有限且可重放的范围。
- 用户已有约束继续适用：CPU、固定 dtype/shape 样本但不设合法值白名单；只比较计算图，不应用交换律/结合律；候选源码由 AI 手写并 hardcode，脚本只采样输入和重放。
- 核对上游 registry、EntryClass、支持文档与模型到层的实际调用，包含继承与别名；用明确层来源证明覆盖关系。
- 优先执行完整选中层的纯 JAX 数值路径，保留精度、shape、参数和输出语义。任何运行时包装裁剪、单设备设置及未验证配置均明确记录；不将每模型一个层外推为整个模型支持证明。
- 正例包括独立计算换序和嵌套包装；负例改变实际依赖/参数/绑定，必须提供数值反例。发现的规范化缺口先复现再修复，并保留独立回归。

## 决策与进展

本目标承接 cond 捕获绑定 bug 修复；该修复已完成，全量 662 passed。

已固定 108 份上游源码/配置文件（逐字节、Git blob SHA-1、SHA-256、Apache 许可证）。语言模型 EntryClass 有 44 项，多模态目录另有 11 项；Stage/Config 合并后有 26 个不同模型名，流水线解析器支持 15 个组件名（14 个在 YAML 使用）。这些入口有别名和重复，不合计为独立模型数。

真实基准使用原类/方法，候选仍为 AI 手写。为执行上游 nnx 层，已通过 `uv add --dev flax` 加入 Flax 0.12.10，JAX 保持 0.11.2；设计见 [开发记录](../../development-docs/sglang-model-layers.md)，来源链见 [覆盖清单](../../references/sglang-model-coverage.md)。

首轮 37 个层运行通过后，调用链测试发现 Qwen3-Omni 文件内定义的同名 MLP 并未被模型构造。没有把文件中的类名当成模型覆盖证据；改为验证实际使用的 GateLogit，去重后为 36 个不同层。流水线 UMT5 明确导入另一份 T5FFN 实现，已分别验证；没有把两个同名模型合并。

修正测试基础设施的依赖注入、NNX 参数接口和 CPU 配置后，全部实际基准可执行。本轮层测试没有发现新的图规范化误判。没有根据比较器结果改变正负标签，也没有用脚本生成 AI 候选。CI 的既有 `uv run pytest` 自动执行全部新检查，不添加重复的整套运行步骤。

## 验证结果

- `uv sync --locked`、Ruff、格式检查、tracing 示例、锁定 lax 原语清单检查通过。
- 全仓库 `uv run pytest -q`：**844 passed in 105.89s**；新增 182 项，包含 108 个层/签名测试和注册完整性、来源链、验收反向检查。
- 36 层 × 2 候选 × 3 签名：**216 个比较组合、1080 组输入/参数数值检查**；所有正例 equivalent，所有负例 different 且有数值反例，没有 unknown 或 skip。
- 所有模型注册行均精确匹配、构造/继承链存在、快照完整且摘要一致。不同模型共享层只复用实际相同的源类，不虚增算法覆盖。
- 前置 cond 修复已通过 20 项专门回归、10 项业务分支回归及四 CPU 设备通信验证。
