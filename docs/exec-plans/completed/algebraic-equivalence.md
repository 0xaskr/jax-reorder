# JAX 函数代数等价比较

状态：已完成并归档。2026-10-13 已完成索引表达式、独立证据校验、固定区域、函数默认自动模式和全量 1600 项测试。用户明确要求不修改受保护文档，相关契约入口同步单列为后续事项。

## 目标与完成条件

让两个 JAX 函数经过交换律、结合律、分配律等改写后，仍能在明确的数学前提下判为等价。函数入口默认执行“契约检查 → 结构比较 → 代数证明”，同时保留显式的结构比较模式。

完成条件：

- 已约定的逐元素、矩阵和求和规则能在给定签名下识别等价表达式，包括矩阵乘法与对应的广播乘法再求和；每个代数等价结果均有可独立复核的证明。
- 结构等价与代数等价在报告中明确区分；代数证明不足、语义不支持或预算耗尽均报告 `unknown`。
- 固定结构的调用、分支、循环，以及显式请求的 JVP/VJP 按相同契约分别验证。
- 保留已有结构模式行为；完成默认函数接口行为迁移及相应回归测试。
- 浮点警告、规则适用条件、验证证据和未支持边界进入文档，不能把抽样相近作为证明。

事实入口：[架构与比较契约](../../../ARCHITECTURE.md)、[两轮比较结果设计](../../references/equivalence-results.md)、[函数与求导契约](../../design-docs/current/function-and-derivative-contract.md)、[区域绑定](../../design-docs/current/region-bindings.md)。下述接口与规则已实现，最终验收证据及实际边界在本文末尾和[开发设计](../../design-docs/current/algebraic-equivalence.md)中记录。

## 已确认的范围与取舍

| 决策 | 本版约定 |
| --- | --- |
| 等价标准 | 按数学代数规则证明，浮点张量按理想实数解释；不承诺浮点执行相同、误差很小或逐位一致 |
| 新增数值域 | 实数浮点；整数、布尔、复数路径继续使用现有结构语义，不新增其代数规则 |

| 观察边界 | 按函数有序输出判断，允许共享、重复计算和可安全忽略的无用纯计算不同；全图语义检查仍保留 |
| 启用方式 | 函数入口默认自动尝试代数证明，可显式退回结构模式 |

| 嵌套范围 | 固定调用、分支和循环结构内部支持代数规则，不改分支顺序、循环边界或控制流结构 |
| 验收场景 | 先完成基础规则及组合验证；不新增真实模型层的代数改写案例，已有模型回归仍运行 |
| 跨算子变换 | 将支持的 dot_general、reduce_sum 与广播乘法统一为带索引的标量乘加和有限求和；matmul、einsum 以实际追踪到的受支持原语为准 |
| 索引范围 | 首期使用给定签名下的静态维度与有限矩形求和域；保留符号索引，不逐个枚举张量元素 |
| 依赖 | 沿用当前 Python 3.12、锁定 JAX/jaxlib 0.11.2 和 CPU 基线；不新增符号计算依赖 |

结论仍限定于给定输入签名、静态参数、追踪环境和输入输出 pytree，不证明一般 Python 函数等价，也不外推未请求的求导模式。

## 接口与结果

### 接口

- `compare_functions` 和 `compare_function_traces` 增加 `equivalence="auto" | "structural"`，默认 `auto`；增加 `algebra_budget=10000`。
- `compare_jaxprs` 和 `canonicalize` 保留完整图结构比较契约和默认行为。
- 新增独立入口 `compare_algebraic_jaxprs(left, right, *, algebra_budget=10000)`，供函数层在核对契约后使用；底层入口不能自行恢复函数 pytree 或追踪上下文。
- 新增 `verify_algebraic_proof(left, right, proof)`，以原始图和证明为输入进行独立复核；校验失败不能返回等价。
- 保留模式报告中的原始结构 `comparison`，新增独立代数报告，包含使用的规则、数学前提、警告、证明及停止原因。
- 模式报告与汇总报告增加 `equivalence_kind`：`structural`、`algebraic` 或 `None`。所有请求模式均等价且至少一个依赖代数证明时，汇总为 `algebraic`；全部由结构证明时为 `structural`。

### 判定流程

1. 核对追踪环境、函数契约以及图合法性。输入输出顺序、dtype、shape 和静态参数等仍是比较前提。
2. 结构匹配直接报告 `equivalent`，沿用原始图对应证据。
   此蕴含也适用于直接调用 `compare_algebraic_jaxprs`：已有结构等价证据即可通过，不再要求进入代数支持域或消耗展开预算；结果保留 `structural` 依据，证明接口可独立复核。
3. `structural` 模式直接保留现有结果；`auto` 模式仅在结构结果为 `different` 时进入代数层。结构检查的 `unknown` 保留原始原因，不通过代数化简绕过。
4. 代数规范表示一致且证明校验通过时报告 `equivalent`，依据为 `algebraic`；适用浮点规则时附带明确警告。
5. 规则无法完成证明、前置条件不满足、证据校验失败或资源超限均报告 `unknown`，同时保留结构差异。

函数契约差异仍可报告 `different`。本版不新增数学不等价证明器，不能由代数规范形式不同直接推出函数数学上不等价。汇总沿用现有 `unknown`、`different`、`equivalent` 的优先顺序，各模式详细结果独立保留。

原先依赖函数默认返回图差异的调用和测试，需根据目的显式选择 `structural`，或迁移为检查自动模式的代数结论与原始结构报告。

## 表示、规则与证明

### 核心方向：统一为带索引的有限乘加

先把受支持的张量运算转换成“某个输出元素如何由输入元素计算”的表达式，再按固定方向规范化。矩阵乘法和求和的差别通过索引绑定表达，不再分别维护矩阵链的右结合形式和归约特例。

例如，`A` 的形状为 `(M, K)`、`B` 为 `(K, N)`：

```text
(A @ B)[i, j]       = Σ(k:K) A[i, k] * B[k, j]
sum(X, axis=1)[i]   = Σ(k:K) X[i, k]
```

其中 `k:K` 表示 `0 <= k < K` 的有限求和。`i`、`j` 是输出位置决定的自由索引，`k` 是只在求和体内有效的绑定索引。

交换律只对同一标量表达式内的加法项和乘法因子排序，不能排序函数输出、输入参数或输出轴。`return x, y` 与 `return y, x` 不能仅靠输出排序判为等价，必须按对应位置比较。结合律先把同类节点展平，分配律再把乘法展开为加法项。

### 内部表示与语义信息

采用以下概念表示；这是逻辑结构，实际模块和类见开发设计：

```text
TensorExpr(
  output_signature=(shape=(M, N), dtype=...),
  free_axes=(i:M, j:N),
  body=Sum(
    bound_axes=(k:K,),
    body=Mul(Read(A, (i, k)), Read(B, (k, j)))
  )
)

ScalarExpr = Constant | Read | Add | Mul | Sum | Apply
```

- `TensorExpr` 保存有序输出轴与完整抽象属性。多个函数输出分别规范化，保持 pytree、叶子位置和每个张量的轴顺序。
- `Read` 保存输入张量身份和有序下标。外部输入身份由输入位置锚定；常量张量保存完整内容及类型。不能用原图临时变量名、节点编号或构造顺序决定数学身份。
- 受支持的中间张量不作为新的自由变量。读取它时，将下标代入上游 `TensorExpr` 的自由轴，并为其内部求和创建新的绑定身份，从而把不同收缩路径展开到同一组输入读取；遇到 `Apply` 或区域边界则保留边界。
- `Sum` 保存绑定索引、各自范围和作用域。索引名可以更换，但范围及所有引用必须同步替换，不能捕获外层索引。
- `Apply` 保存已支持但没有代数展开规则的纯算子及其完整参数。只对已证明等价的输入使用同余规则；不能把不支持的算子、effects 或不透明参数包装成 `Apply` 后放行。
- DAG 节点及证明保留原图来源、类型、形状和算子参数。参与比较的数学表达式与用于审查适用条件的源语义分别保存；源节点编号不进入规范形式的数学身份。
- 有限浮点标量常量按实际存储值转换为精确有理数，不按十进制打印文本解释，不用浮点计算合并系数。常量张量不为规范化而全部展开成标量节点。
- 复用已有语义编码能力，完整比较常量和元数据。哈希只用于加速查找，相等仍以精确内容比较为准；共享 DAG 和缓存减少重复工作，原图保持不变。

### 从 JAX 原语到索引表达式

| 原语或操作 | 转换方式 | 必须核对的条件 |
| --- | --- | --- |
| add、mul、sub、neg、非负整数幂 | 在输出自由索引处生成标量表达式；减法改为加负项，幂进入有限乘积规范化 | 实数域、类型、定义域及实际广播映射 |
| broadcast_in_dim 与逐元素广播 | 输出索引映射回输入轴；被扩展的长度为 1 的输入轴读取下标 0，新插入的轴不进入输入下标 | 轴位置、原维度长度与重复次数；不能只检查输出 shape |
| transpose、squeeze、插入单位轴 | 按轴映射替换 `Read` 下标，输出轴位置继续固定 | 排列方向、被删除轴确为长度 1；一般 reshape 不直接当作轴置换 |
| reduce_sum | 被归约轴变成新的绑定索引，未归约轴按原顺序映射到输出；keepdims 按实际追踪出的单位轴操作处理 | 归约轴、空域、输出维度及累加类型；不把其他 reducer 当作加法 |
| dot_general | 成对收缩轴使用同一个绑定索引；成对批次轴使用同一个输出自由索引；其余轴分别映射到左右输入的非收缩轴 | 维度配对与范围相等；输出轴按批次轴、左侧剩余轴、右侧剩余轴的语义顺序映射；完整核对 primitive 参数 |
| 其他受支持的纯算子 | 保留 `Apply` 边界，递归证明实参等价 | 参数、输入输出类型和区域绑定一致；不新增激活函数、除法、对数等恒等式 |

`matmul`、`einsum` 不单独解析 Python 源码或表达式字符串，以实际 jaxpr 为入口。批次广播也必须从实际轴映射得到；einsum 若涉及尚未支持的对角读取、gather 或其他结构，不因它在数学上是收缩就自动获得支持。

类型转换、精度、累加类型、布局和分片必须进入转换与规则条件。`convert_element_type` 继续作为显式边界；不能因为公式相同就忽略不同的精度参数。首期跨算子互认先覆盖默认浮点精度、输入/输出/累加类型兼容且无额外转换的路径；非默认精度、额外累加类型或特殊分片须有专门适用条件，未审查时保留原边界或返回 `unknown`。

不同原语的参数不要求机械地逐项相同：例如 dot 与 mul/reduce 本来就有不同的参数集合。证明必须分别核对它们到理想实数表达式的转换条件，并保留各自参数及浮点警告，不能简单删掉参数再比较。

语义参考：[StableHLO dot_general](https://openxla.org/stablehlo/spec#dot_general)、[JAX dot](https://docs.jax.dev/en/latest/_autosummary/jax.lax.dot.html)、[JAX reduce_sum](https://docs.jax.dev/en/latest/_autosummary/jax.lax.reduce_sum.html)。这些定义用于核对索引映射，代数重组另依赖本计划声明的理想实数解释；实现仍以仓库锁定版本为准，不能依据更新后的网页静默扩大适配范围。

### 固定方向的规范化流水线

目标形式是稀疏的“项之和”。每项包含精确系数、有限求和域和标量因子多重集；求和索引仍是符号，不枚举范围中的每个值。一个概念上的项为：

```text
Term(
  coefficient=1,
  bound_axes=(s0:K, s1:L),
  factors=(Read(A, (i, s0)), Read(B, (s0, s1)), Read(C, (s1, j)))
)
```

依次执行以下步骤，每一步生成可校验的局部证明：

1. **转换与轴映射。** 校验原语语义，将支持的节点转换为索引表达式，组合广播、转置等映射；每次引入绑定索引使用新的身份。
2. **展平与展开。** 展平嵌套的 `Add`、`Mul`；将乘法对加法展开，减法和负号归入精确系数。仅向展开方向执行，不同时反向提取公因子。
3. **求和线性化。** `Sum(k, a+b)` 变成两个求和项。满足有限、独立矩形域条件时，把嵌套求和合并到项的求和域；与求和索引无关的因子可移入求和体，反方向不作为规范化策略。
4. **处理边界范围。** 长度为 1 的绑定轴代入下标 0；没有被任何因子引用的绑定轴贡献其范围长度，不能直接删除。空求和在定义域及纯度条件满足时为零；自由输出轴仍保留在输出签名中。
5. **规范绑定索引。** 按下一节的方法规范索引身份和求和轴顺序；保留固定自由索引、张量身份及每次读取的下标位置。
6. **排序与合并。** 标量因子排序并保留重复次数；对求和域与因子结构一致的项合并精确系数，再按完整项键排序。零/一消去仍须通过定义域检查。
7. **比较与复核。** 逐个有序输出精确比较规范表示，再独立校验证明；不能仅凭相同摘要判为等价。

实现按子表达式递归生成项表：`Add` 合并子项表，`Mul` 对子项表做有预算限制的笛卡尔积并分离绑定索引，`Sum` 为每个子项附加求和域，再完成边界处理和项键规范化。上述步骤是逻辑顺序，不是对原图各扫描一次；例如求和线性化产生的加法仍须参与外层乘法展开。

展开两个求和的乘积时必须先分离其绑定索引。例如：

```text
(Σ(k:K) A[k]) * (Σ(k:K) B[k])
  -> Σ(u:K, v:K) A[u] * B[v]
```

不能变成 `Σ(k:K) A[k] * B[k]`，后者少了交叉项。有限求和换序仅适用于独立的固定范围；带依赖上下界的求和、动态索引域和一般循环不使用此规则。

`Apply` 或区域边界会阻止跨边界展平；其参数表达式可以独立规范化。例如可以先证明 `a+b` 与 `b+a`，再在相同参数条件下证明两次 `sin` 调用等价，但不把 `sin(a+b)` 展开。

### 绑定索引的确定性规范化

不能按原索引名或首次遍历顺序重命名；两张等价图可能从相反的收缩顺序生成索引。实现使用确定性的连接关系规范化：

1. 为每个已展开的项建立带颜色和端口的连接图。绑定索引的范围进入颜色；输入张量身份、常量、自由输出索引及 `Read` 的轴位置构成固定锚点，标量因子之间允许换序。
2. 按范围与连接关系细化候选分组，先区分不可能互换的索引；分组与排序使用完整结构键，不能依赖内存地址或原图编号。
3. 对仍无法区分的候选，在预算内搜索允许的索引编号，序列化求和域和排序后的因子，选择字典序最小的表示。编号按 `s0`、`s1` 等生成，范围随编号保留。
4. 记录合法的索引双射及所有引用的替换，供证明器检查。高度对称的表达式若搜索超预算，返回 `unknown`，不能用一次启发式遍历结果声称已经得到唯一表示。

这一步负责消除求和变量改名、独立求和换序及收缩路径造成的表面差别；不会交换固定输出轴，也不会改变同一输入张量各轴的意义。证明校验器只需验证最终索引替换合法，不需要信任搜索算法或重复寻找最小编号。

### matmul、sum 与逐元素运算的统一示例

设 `A:(M,K)`、`B:(K,L)`、`C:(L,N)`，矩阵结合律的两侧分别为：

```text
((A @ B) @ C)[i,j] = Σ(l:L) (Σ(k:K) A[i,k] * B[k,l]) * C[l,j]
(A @ (B @ C))[i,j] = Σ(k:K) A[i,k] * (Σ(l:L) B[k,l] * C[l,j])

统一后：Σ(k:K, l:L) A[i,k] * B[k,l] * C[l,j]
```

对于形状兼容的 `A`、`B`、`C`，分配律也由同一套标量规则得到：

```text
(A @ (B+C))[i,j]
  = Σ(k:K) A[i,k] * (B[k,j] + C[k,j])
  -> Σ(k:K) A[i,k] * B[k,j] + Σ(k:K) A[i,k] * C[k,j]
```

矩阵乘法与广播乘加的首期互认用例：

```python
A @ B
jnp.sum(A[:, :, None] * B[None, :, :], axis=1)
```

两侧都应得到 `Σ(k:K) A[i,k] * B[k,j]`。同理，在相应轴映射下，连续两次独立求和与一次多轴求和可得到相同的求和域。

矩阵不可交换性由下标连接自然保留。即使 `A`、`B` 都是同尺寸方阵：

```text
(A @ B)[i,j] = Σ(k:K) A[i,k] * B[k,j]
(B @ A)[i,j] = Σ(k:K) B[i,k] * A[k,j]
```

标量乘法因子排序后，下标连接仍然不同；自由索引不能与绑定索引互换，因此不能通过排序把它们判成相同。

### 规范化的保证与资源边界

本方案追求已声明规则范围内的共同表示，不能仅凭“所有改写都有固定方向”就承诺任意图都能归一。实现设计必须说明各阶段的终止方式，以及索引重命名、展开与项合并的结果为何不依赖原图构造顺序，并用不同改写路径的测试验证。

承诺的正确性方向是：**规范表示相同且独立证明通过，则在记录的数学前提下等价。** 表示不同、某个转换不支持或规范化未完成，都不能反向推出数学不等价；不承诺对任意 JAX 程序、任意恒等式或常量张量恒等式的完备判定。

维度长度不直接决定展开节点数量。例如 `K=4096` 时仍保留 `Sum(k:4096, ...)`，不生成 4096 个加法节点；这里的“展开”指代数结构的展开。分配律产生的项数及索引对称性搜索仍可能指数增长，必须计入预算并在分配大量内存之前停止。

### 数学前提与安全边界

- 参与实数规则的值必须在声明的数学解释下有定义且有限；报告记录这项前提，不把它解释成对实际浮点执行的保证。
- 非有限常量、未知数值语义以及无法满足前置条件的表达式保守拒绝。不得未经定义域论证，通过乘零、消项等规则删除部分函数调用。
- 不因某个节点不影响输出就跳过其语义检查。未知 effects、不透明参数、隐式有序操作和受保护的顺序根不能当成普通代数变量或无用计算删除。
- 固定区域边界继续保留；不得以“无用纯计算”为由删除尚未论证可安全忽略的循环或调用。
- 新增代数层前补齐函数入口对原始输入抽象属性的检查，包括当前 `_abstract` 尚未保留的属性；无法忠实保留的追踪签名返回 `unknown`。

### 嵌套与求导

在对应的 jit、cond、scan、while 区域内递归证明，不移动运算跨越区域边界。沿用已有私有接口同步置换能力，保留实际实参/形参绑定、分支顺序和对外端口位置。

循环证明必须同时覆盖初始状态、条件、反馈绑定、循环体和输出关系；不能仅证明循环体的公式相等。JVP/VJP 使用实际追踪后的程序，包括梯度累加和已物化的自定义规则；不得由前向等价推断梯度等价。

### 证明与预算

代数改写会改变节点数量和共享方式，不能沿用要求原图节点一一对应的结构双射作为证明。

- 每步记录规则、原图来源、输入表达式、结果以及适用条件，形成可以共享子证明的推导 DAG。规则包括 dot/reduce 转换、轴映射、绑定索引改名、求和线性化、独立求和合并、标量交换/结合/分配及同类项合并。
- 独立校验器从原始图检查局部规则和证明连接，不能重新运行规范化器并相信其输出代替验证。
- 索引证明必须校验作用域、范围、自由/绑定身份、轴位置及乘法移动时的独立性；仅证明标量加乘交换不足以证明张量表达式等价。
- `algebra_budget=10000` 作为一次底层图对比较的总预算，各嵌套区域共享；函数的各个请求模式单独计数。
- 预算按确定性工作量限制新展开项、表达式节点、索引编号搜索和证明步骤；精确系数运算也须限制资源增长。展开前检查预计成本，超限返回带位置和原因的 `unknown`。
- 保留已有结构搜索预算，不以运行时间代替代数工作量预算；不得先构造指数规模中间结果再检查超限。

- 不新增真实模型的代数改写验收、高阶求导、GPU/TPU 执行或一般数学不等价证明。证据为进程内对象，尚无持久化格式。
