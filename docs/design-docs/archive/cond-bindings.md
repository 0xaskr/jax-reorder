# cond 实参与形参的同步规范化

> 状态：早期设计，接口与覆盖范围已被后续实现替代。当前规则见 [完整图](../current/complete-graph.md)、[区域绑定](../current/region-bindings.md)及[函数契约](../current/function-and-derivative-contract.md)；基础原则仍可追溯。

本页保留 cond 首轮修复及四层验证记录。后续已通过[完整图有界搜索](../current/complete-graph.md)支持多个全分支未使用的槽位，并补齐私有返回端口及[循环/调用绑定](../current/region-bindings.md)；下文第 5 条描述的是首轮边界。

## 问题与范围

JAX 可按首次引用顺序捕获闭包参数。RMSNorm 的独立 sigmoid 提前后，cond 实参从 `(x, scale, gate)` 变为 `(gate, x, scale)`，分支形参同步改变，实际计算不变。直接比较调用输入位置会产生误判。

本规则只允许 cond 的数据实参与所有分支形参使用同一个置换。固定外部函数输入输出、分支选择值、分支顺序、结果端口、常量、共享关系、抽象值、effects 和其他参数；分支内普通运算的操作数位置不变。不内联、不删除输入、不应用代数改写。lax.switch 也使用 cond 原语。

## 算法

1. 在父图 BFS 编号前，先规范化 cond 各分支内部的方程和嵌套 cond。
2. 按原分支顺序，依次查看有序输出、BFS 节点的有序输入，记录分支形参首次出现的槽位。跨分支共用一份槽位顺序；不能各自独立排列。
3. 用同一置换调整 cond 数据实参与每个分支的 invars；保持变量对象和变量的实际引用不变。调试参数名称随形参同步移动。
4. 父图 BFS 使用调整后的输入顺序编号，再执行已有深度排序和完整结构比较。仅在最后更改比较键会让父图生产者编号仍受旧捕获顺序影响，因此不采用这种做法。
5. 所有分支均不引用的槽位保留；多于一个时无法由使用位置确定唯一顺序，返回 unknown，不假称完整规范化。未使用方程等已有 unknown 规则继续生效。

JAX 0.11.2 的 `conditionals.py` 中，`_cond_typecheck` 要求所有分支具有相同输入签名，`_cond_lowering` 将同一组 `args` 传给每个分支。除 `branches` 外，本版本已审核的参数是按分支排列的 `branches_platforms`；它不随数据输入置换。未知参数明确拒绝，防止遗漏潜在的位置语义。

重建分支必须保留原图，缓存按图对象身份持有对象，防止临时图释放后复用对象 ID 导致错误命中。原始分支及重绑后的分支可共享内部已规范化的子图。

## 验证要求

- 复现 gated RMSNorm 的 FP32、BF16、小形状闭包换序，真假分支均执行；保留显式传参对照与错误绑定负例。
- 父图独立计算的结果作为捕获实参、直接返回输入、多分支、嵌套 cond、多输出、共享与重复实参、不同 dtype/shape、常量和未使用部分。
- 仅换实参、仅换一个分支形参、修改分支顺序/选择值/数值常量不得匹配。
- 返回图通过 JAX 校验、执行与幂等检查，原始图及外部接口不变。
- 原通信闭包换序案例应从 different 改为 equivalent，继续执行双/四 CPU 设备验证。
