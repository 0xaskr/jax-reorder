# DeepSeek-V4.1-Flash mHC 残差层的代数优化验证

## 来源与选择

基线来自 [Inferact/tpu-megakernels PR #3](https://github.com/Inferact/tpu-megakernels/pull/3) 的纯 JAX 参考实现，固定提交 `d11defb7e5e2fdd8d355b2f6225c74d2a15fa1e1`，下载时 PR 状态为 OPEN。模型身份为 DeepSeek-V4.1-Flash。[完整源码、配置、调用上下文及许可证](../../tests/fixtures/deepseek_v41/manifest.json)按 SHA-256 校验。

选定完整 `reference.py:113` 的 `hc_post`：将子层输出扩展回 4 条残差流，与流间混合结果相加。原始模型在 attention 和 FFN 后调用它；模型配置是 `hc_mult=4`、`dim=5120`。使用完整函数定义及原装饰器，不重写 base；加载器只隔离无关的 checkpoint、量化与服务导入。`hc_mixes`、`hc_split_sinkhorn` 和 `hc_pre` 也原样加载，用于上游 20 次 Sinkhorn 的完整调用上下文验证。

## 公式、候选与接口

输入为子层输出 `x[..., D]`、残差 `r[..., H, D]`、`post[..., H]`、`comb[..., H, H]`。完整输出为 `cast_x_dtype(post[j] * x[d] + sum_i comb[i,j] * r[i,d])`；所有参与值先按原代码转为 FP32，最后一次类型转换保持原位。

AI 手写候选放在 [candidates.py](../../examples/deepseek_v41/candidates.py)：

- `post_matmul`：把显式 `H×H×D` 广播乘积与归约替换为 `comb.T @ residual`，保留 post 分支和最终转换。代数依据为相同有限收缩索引，收缩规模仍为 `O(H²D)`，逻辑中间张量由 `H²D` 降到 `HD`。是否降低实际内存和延迟必须通过编译结果与计时确认。
- `post_blocked`：把来源流归约拆成两个连续区间，再结合两段与 post 分支。逻辑广播中间张量最大约减半；验证区间覆盖、无重叠及下标绑定。
- 错误反例：遗漏 comb 转置、post 系数减半、提前舍入流间累加到 BF16；均保留相同输出形状，必须拒绝证明并给出实际数值见证。

保留有序输入输出、pytree、dtype、shape、静态参数、嵌套 JIT 与所有计算。代数证明限定理想实数，必须报告舍入/溢出/NaN/Inf/有符号零警告；不同 dtype 的转换不得作为结合律消去。前向、JVP、VJP 分别追踪、证明和复核。

- 来源：逐文件哈希、固定提交、原始 AST 定义与真实调用位置。
- 正确性：FP32/BF16、多个 batch/sequence/hc/hidden 形状、真实 `H=4,D=5120`，随机与抵消输入，NumPy 逐流参照和独立导数公式。
- 证据：结构结果、代数证明、独立证明校验分别报告；反例、预算拒绝及被篡改证据不可通过。完整 mHC 上下文使用上游混合系数产生过程。

- 发现问题先缩成失败回归，算法修改前补充根因与通用设计，不为模型或候选硬编码白名单。

## 已确认缺口：纯 JIT 的 VJP 残差接口

首轮矩阵乘法与分块两个候选在 FP32/BF16 均通过 forward、JVP 代数证明，但 VJP 返回 `normal forms differ`。原始 VJP 的 JIT 前向输出保存广播后的残差，候选保存矩阵形状的残差；这些私有返回接口和后续反向调用组合后才具有相同含义。仅用于定位的无 JIT 版本可证明，证明缺口位于调用组合，而非梯度公式。

通用修复设计：对完整参数 schema 已知、无 effects、无 donation、无显式 sharding/layout、空 mesh、默认 inline/keep_unused/compiler options 的普通 JIT，按实际有序实参代入子图，保留所有返回位置、常量及内部语义。子图中的其他控制区域仍保留边界，并把其 barriers 带回父图。非默认调用继续使用原来的有边界表示。结构比较不改变。

不得借内联丢弃部分函数：调用方已求值但子图未读取的部分表达式继续拒绝透明化；被父图丢弃的部分函数返回值不能因原语名为 jit 而跳过无根检查。全部图、参数和 abstract value 仍先经过原始校验；独立证明校验器从原图重新执行同一受审查的语义适配，再核对代数推导。回归包括残差接口变化、错误连接、捕获常量、空返回、嵌套控制区域、无根部分函数及非默认元数据。

## 已确认缺口：低精度反向转换的默认分片描述

纯 JIT 组合修复后，矩阵候选的 FP32 三模式均证明。BF16 VJP 的剩余差异来自 JAX 转置规则自动为 `convert_element_type` 加入的空 AbstractMesh / 全 None PartitionSpec；其 rank 随广播中间量改变，旧转换器将这种默认描述当作不透明张量操作，无法复合 squeeze/reduce 的索引。修复仅接受与输出 `core.ShapedArray(shape, dtype)` 默认描述完整编码相同的 sharding，并规范成原来的无显式放置逐点 cast；不同 memory kind、逻辑设备、非默认分片或上下文继续保留，舍入转换本身绝不删除。

## 完整上下文的共同调用复用

20 次 Sinkhorn 的完整上下文在 10,000 及 200,000 预算下均停在索引化简。直接把两侧相同的非线性归一化 JIT 都展开，造成重复表达式工作；增加预算不能作为主要修复。

设计采用函数合同：从已验证的两侧区域图提取完全相同的默认纯 JIT 子图。精确键包含全部输入输出抽象值、常量内容、节点顺序、引用、原语身份、参数、嵌套图和上下文，仅排除已有契约允许忽略的 JIT 诊断名称。键相等的调用可作为同一个未解释函数，实参仍逐项转换并比较，所有返回口和调用 barrier 保留。只在两侧共有时保留，否则按上述严格规则展开。未知参数和 effects 仍拒绝，函数默认视为部分定义，禁止乘零或消项抹去它。

比较器和独立校验器分别从已通过原图对应校验的图重新生成共同调用集合；校验器不调用规范化器或索引搜索，也不信任证据给出的“相同”标记。该规则只运用相同函数作用于相同实参的合同，不近似非线性计算，不省略 20 次迭代或改变模型输出。

区域规范化会改变内部端口排列，因此共同调用键从原始子图建立，再使用已核验的 `GraphCorrespondence` 将适配图的实参和结果端口映回原始接口。不能直接拿新槽位调用旧函数符号。实际堆栈采样还发现 `order_key` 每次只缓存单次调用，反复遍历同一个大型函数键；生成器和校验器各自增加局部生命周期的排序键缓存，保留完整内容相等判断，不改为摘要判等。

BF16 的二次采样进一步定位到 `map_factors`：标量 cast 内部重新排序时没有沿用调用方缓存。索引替换、域见证及前缀指标转换传递同一个局部排序函数，递归进入标量参数仍保留独立绑定作用域；校验器独立建立自己的缓存，不共享规范化结果。

## 分块归约转置的零填充

分块候选的 VJP 把两段梯度用 `pad` 零扩展后相加；旧表示将 pad 当作不透明张量操作。新适配只处理零值、非负边界、无内部间隔的静态 padding，并逐项证明扩展后的表达式在整个输出矩形域内读取合法且全定义。通过校验的输入读取与已求值的共同调用返回张量记录实际 shape；部分标量函数、未知张量来源、越界读取都不得扩展。

合法扩展记为 `body(i-low) * (I(0<=i<low+size)-I(0<=i<low))`，各轴相乘；零域与全域的指标直接是 0/1。输入下标经原有符号索引合成，连续分块的前缀指标精确抵消，缺口或重叠保留。共同调用的求值依赖始终保留在部分定义 barrier 中；其已求值返回张量的有效坐标读取为全定义，读取消项不能删除调用 barrier。

三条流的实际 VJP 暴露单位分块边界：JAX 把第一段梯度的读取固定成下标 0，而另一段前缀仍写为下标 i。在保留 `I(0<=i<1)` 的前提下，可用整数约束 i=0 规范化同项内的全定义读取。生成器和校验器共用这一小型整数条件检查，不能删除指标自身，不能将 `I(0<=i<2)` 也按单点处理，也不改写部分函数项。

## 实际证明与数值结果

2026-10-14，Python 3.12.3、JAX/jaxlib 0.11.2、CPU、x64=False。真实 `B=1,S=1,H=4,D=5120` 下，两种候选的 FP32/BF16 前向、JVP、VJP 均由代数证明通过，并独立复核及 CPU 编译；原结构报告全部为 `different`。完整上游 20 次 Sinkhorn、`hc_mixes`、`hc_pre` 调用上下文也全部通过，下面记录默认 10,000 预算内的实际工作量。

| dtype / 候选 | 独立层 forward / JVP / VJP | 完整 mHC 上下文 forward / JVP / VJP |
| --- | --- | --- |
| FP32 / matmul | 209 / 743 / 1221 | 494 / 1471 / 3655 |
| FP32 / blocked | 408 / 1289 / 2468 | 693 / 2017 / 4954 |
| BF16 / matmul | 293 / 974 / 1500 | 581 / 1708 / 3942 |
| BF16 / blocked | 522 / 1599 / 2876 | 810 / 2333 / 5372 |

独立层使用 3 个随机种子和抵消样本，与 NumPy 逐流前向、显式 JVP/VJP 公式比较。候选最大绝对误差如下；这些是采样观测，不是普遍浮点误差界。FP32 的执行阈值为 `rtol=2e-5, atol=2e-4`，低精度输出为 `rtol=atol=0.016`。

| dtype / 候选 | forward | JVP | VJP |
| --- | --- | --- | --- |
| FP32 / matmul、blocked | 2.3842e-7 | 3.5763e-7 | 1.9074e-5 |
| BF16 / matmul | 4.8828125e-4 | 1.953125e-3 | 1.220703125e-4 |
| BF16 / blocked | 9.765625e-4 | 1.953125e-3 | 1.220703125e-4 |

三个错误候选在两种 dtype 的三个模式全部拒绝证明。前向见证中，遗漏转置最大差约 1.003，系数减半约 0.5，提前 BF16 舍入约 0.003。完整上下文的两个输出与 base 实际执行比较：FP32 的 post 最大差 4.7684e-7、pre 为 0；BF16 本组样本均为 0。

验证范围是原始完整 mHC 函数、明确的追踪签名和固定随机参数。硬件仅有 CPU，性能及执行结论限定本环境；实数证明仍附带浮点警告。新增模型测试归入 CI 的 `business` 分组。

## CPU 性能与取舍

Intel Core Ultra 7 155H，22 个逻辑 CPU。所有验证进程结束后，使用相同随机输入，对三个编译后的函数各 warmup 3 次、交错运行 200 次，每次 `block_until_ready`；编译时间不计入中位延迟。所有行均为 `H=4,D=5120`，加速比为 base 中位延迟 / 候选中位延迟，大于 1 表示候选更快。

| dtype | B / S | base μs | matmul μs / 加速比 | blocked μs / 加速比 |
| --- | --- | --- | --- | --- |
| FP32 | 1 / 1 | 27.79 | 26.40 / 1.053× | 41.09 / 0.676× |
| FP32 | 8 / 1 | 89.97 | 119.09 / 0.755× | 169.29 / 0.531× |
| FP32 | 1 / 128 | 416.91 | 859.62 / 0.485× | 1024.21 / 0.407× |
| BF16 | 1 / 1 | 44.39 | 40.04 / 1.109× | 53.38 / 0.832× |
| BF16 | 8 / 1 | 162.32 | 176.76 / 0.918× | 214.03 / 0.758× |
| BF16 | 1 / 128 | 655.76 | 1511.91 / 0.434× | 1225.51 / 0.535× |

矩阵改写在本组单 token 样本有小幅收益，大批量与长序列更慢；分块候选在本组 CPU 形状均更慢。该结果不支持把任一候选作为普遍更快的替换。

XLA 内存报告中 base 的临时缓冲始终为 0，说明原广播归约已经融合，不能把逻辑 `H²D` 张量视为实际内存分配。`B=S=1` 时，matmul 的临时空间为 FP32 81,920 字节 / BF16 163,840 字节，blocked 为 82,016 字节；其他形状同样增加临时空间。因此本实验没有得到实际内存节省。原始逐次样本、p10/p90、编译内存与 cost analysis 由 runner 的 JSON 输出保存，不能从当前 CPU 数据推断 TPU/GPU 性能。
