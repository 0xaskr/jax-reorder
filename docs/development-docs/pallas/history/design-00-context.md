# JAX / Pallas 等价比较：设计与验证

## 第一版范围：分布式程序的设备局部视角

2026-10-19 用户澄清：第一版比较分布式计算中单个 device 执行的 Pallas kernel，
不要求整个程序只使用一个 device。mesh 可以存在，包括多维 mesh；不要求展开整个
mesh、组装所有设备的输出或证明全局通信协议等价。下文早期多 TPU 整体比较目标保留为后续工作。

- 每侧仍限定一个 `pallas_call`，比较其设备局部的完整计算图、输入输出和副作用。
  单设备视角不等于单 program；静态多维 grid、规则分块与矩形访存已接入 core 规范化，
  一般动态地址和布局仍待扩展，具体范围见 §9.14。
- mesh 是环境上下文。完成局部输入输出及资源对应后，不影响局部语义的 mesh 拓扑不作为
  额外的一致性条件；若设备坐标、轴大小或分片映射影响局部值、索引、分支或通信目标，
  则必须保留其依赖和绑定。可以显式参数化这些环境量，但不能抹去轴对应关系或取值约束。
- 本地与远端 DMA、signal/wait/read 若出现在局部图中，仍保留操作、通信目标、Ref、
  semaphore 绑定和顺序。通信逻辑检查按需读取相关对端的行为与接口约束；局部图相同
  不自动保证发送者、接收者或进展正确，也不能把收到的数据当成无来源约束的任意相同值。
- 先补局部图覆盖，再补代数 lowering。纯死计算删减仍只放在代数 lowering；
  结构层保留收到的完整图。局部结论必须标明环境及通信接口条件，不能升级为全分布式程序等价。

例：局部 `y = x + 1` 不依赖 mesh 拓扑；`peer = (device_id + 1) % mesh_size`
则依赖设备坐标和轴大小，通信目标不能丢弃。官方[分布式 Pallas 示例](https://docs.jax.dev/en/latest/pallas/tpu/distributed.html)
也使用设备坐标计算邻居和本地缓冲区索引。

设备局部入口已实现为 `compare_pallas_kernels`，调用方传入包含唯一 `pallas_call` 的完整
jaxpr，入口提取实参来源和具名轴绑定；结果标明 `scope="device_local"`。现有公共全函数/
结构比较仍完整编码 mesh，契约保持独立。局部入口与资源检查见 §9.13，多维地址覆盖见 §9.14。

### device_id 相关逻辑与通信检查

2026-10-19 进一步澄清：用户不关注 `device_id` 的具体编号，同时要求关注它造成的
计算/分支差异，以及发错设备、等待无法满足等通信问题。第一版同时跟踪这两类逻辑，
设备局部视角不意味着忽略相关对端的行为。

- `device_id` 按源图中的符号值及绑定参与比较，不固定某个编号或枚举所有设备。
  它参与的算术、分支、访存索引、通信目标和等待依赖均保留；不能因为编号本身不是目标，
  就删除这些表达式。已知来源和约束继续保留，不能把同范围的两个值自动认作同一坐标。
- 不把专门解析设备编号或推导范围作为所有局部结构比较的额外准入条件。
  当分支可达性、地址或路由合法性、等待配对的判断实际需要范围时，再从外层 jaxpr、
  调用绑定及具名轴环境取得证据。逻辑轴坐标可携带 `d ∈ Z, 0 <= d < N, N > 0`；
  `axis_index` 可以位于 kernel 内，通过外层轴绑定取得域，不要求外层存在名为 `device_id`
  的变量。物理设备编号不能未经映射就套用逻辑坐标范围。
- 通信检查须保留本端和相关对端在什么条件下、向哪个目标/Ref/semaphore 读写、发送或等待，
  以及计数和因果依赖。只有本端 `wait` 不能推出对端存在匹配的 `signal`；目标合法也不证明
  整个等待依赖能完成。范围、对端行为或同步关系不足以完成所需证明时，明确报错/拒绝该检查，
  不猜测设备范围，不把尚未证明的协议当作正确，也不以检查失败推出两个程序不等价。
- 结构等价与通信有效性分别报告；两个图即使包含相同的错误，也不能因此宣称通信正确。
  现有完整结构入口仍可独立比较，新增局部入口不得把结构匹配伪装成已通过通信检查。

验证需要覆盖：`d == 0` 与 `d == 1` 的分支差异；在 `N > 1`、`0 <= d < N` 下，
`(d + 1) % N` 与 `d + 1` 在末端设备的路由差异；错误通信目标、缺失发送/信号及循环等待；
缺少必要范围或对端上下文的拒绝路径。环形邻居必须写 `(device_id + 1) % mesh_size`，
`device_id + 1 % mesh_size` 按运算优先级是另一个表达式，不能擅自修正源图。

局部入口已保留相关逻辑轴及大小，并将外层 `axis_index`、常量和纯运算绑定到局部参数。
默认只比较结构；显式设置 `check_protocol=True` 才重放资源与通信检查。远端检查复用已有
单轴、有限静态协议规则，包含路由越界和等待环检查；一般符号协议及多轴全局通信证明仍未实现。

## 2026-10-19 覆盖与代数接入记录

2026-10-19 后续实施顺序：用户指定先补齐覆盖，再接代数。以锁定源码的官方 API/原语矩阵
核对实际追踪、参数和嵌套组合，补齐缺口后再把中间层完整输出投影接入可信 SymPy。
保留 effects 的支持检查和图/数值/硬件证据分离，见[执行记录](../../../exec-plans/completed/pallas-coverage-and-algebra.md)。

覆盖修复设计：官方 `run_state`、精确类型 `Einshape`、pipeline 的父操作数捕获与
显式 allocation 索引函数必须进入完整参数/区域比较。索引函数以锁定源码相同的
输入抽象值追踪；没有父端口绑定的 tracer 捕获明确拒绝。未知 HiPrim 仍拒绝。
默认展开 pipeline 暴露内部无使用结果槽位的阶乘搜索：先用各子图对应返回值的
结构类别（字面量、形参、常量、生产原语）分组，类别全部唯一时直接排序；仍有
歧义时先保留原阶乘预算预检，通过后只枚举同组端口，避免部分拆分让大图由快速
拒绝退化为长时间枚举。类别不依赖变量名或原槽位，不作为匹配证据；仍复核完整结构
及父子/循环反馈绑定。
反例必须覆盖同原语不同操作数、捕获值变化、allocation 索引变化与未知参数。

代数接入设计：公共 auto/algebraic 路径先完成结构与接口检查；含 Pallas 时将
已支持的单调用中间层 `normalize_view` 输出投影冻结给隔离 SymPy worker。
不以投影字符串相同代替 CAS，也不把局部表达式不同报告成程序不等价。
值读取带完整全局索引，定义条件、dtype/cast 与非有限规则复用现有 SymbolicBuilder；
地址覆盖、输出初始化、DMA 版本/等待证明仍是消去状态的前置条件。
规则、投影证据和 DMA progress 假设随数学结果返回，分析和 CAS 共享代数预算。
首批接入一维静态 Blocked、尾块 mask、正反向网格、默认 JIT 包装与已支持的局部
scratch/DMA；包含远程协议、semaphore 计数、嵌套控制流、非默认执行选项或分片
组装但无法完整投影时，明确拒绝代数转换，保留其结构比较能力。
Pallas/JAX 共享同一外部位置输入与完整输出坐标，逐点代数改写由可信 SymPy 判定。
大输出的反例探测包含端点与中点（总量仍最多 16），避免 `program_id` 在前两个
坐标相同就找不到分块变化的反例。探测只实例化坐标，输入仍为符号；只有 CAS 在
完整输出坐标给出 False 才报告不等价，探测点全部相同绝不能推断整个输出相同。

## 2026-10-19 范围修订：Pallas 层只做完整计算图比较

用户已明确：Pallas 层与现有 JAX 结构层采用相同职责。完整保留运算、参数、
嵌套区域、Ref/信号量绑定与副作用顺序，允许独立纯计算重排。128/256 分块、
循环改写和不同通信协议的数学等价交给后续代数 lowering 与可信 SymPy；不能
要求先完成这些证明才能进行结构比较。下文早期 M1/M2 的跨分块和协议分析目标
作为后续能力保留，不作为本轮结构交付的完成条件。

语义图忽略耗时，不模拟 DMA 进展或信号量计数。signal/wait/read 与 DMA
start/wait 均是保留的操作节点；资源引用、计数/设备/索引数据依赖及同一区域内
全部有副作用操作的相对顺序参与比较。信号量重命名采用一致的资源双射，
不能按变量名、最终计数或“最近的 wait”匹配。`signal(1); signal(1); wait(2)`
与 `signal(2); wait(2)` 应结构不同。跨循环和分支保留区域及绑定，不展开调度。

DMA start 只可在普通图规范化中与确定独立的纯计算换序，不跨其他副作用节点，
不要求与 wait 相邻，也不合并节点。循环不变量、地址覆盖、等待配对及死锁分析
不是结构比较前置条件。未使用纯计算仍在完整结构图中保留，仅代数 lowering
可以按已记录的纯死代码规则删减。

本轮复用已有 Graph/BFS/无根搜索和原图对应复核；源对象的 Pallas 编码集中在
`core/adapters/pallas`。现有 ProgramView 受限规范化消费者保留，不自动用于公共
结构判等。实施与验证见[结构比较计划](../../../exec-plans/completed/pallas-structural-comparison.md)。

官方 `emit_pipeline` 的组合追踪暴露了无根搜索的退化：一旦任意 Ref effect 含
参数内变量引用，原算法便全局禁用孪生节点剪枝，连与这些引用无关的重复纯节点
也需枚举。此次只收紧剪枝条件：记录参数引用的全部目标；候选顶点没有参数入边、
完整参数标签及实际邻接均相同时才合并搜索分支。节点仍全部保留，最终证书与原图
双射检查不变。含参数入边或不同参数绑定的候选继续完整搜索；预算耗尽仍显式失败。
同一搜索中共享的嵌套区域排序键复用已有身份缓存，候选独有的重命名参数缓存则
逐候选释放，避免重复展开不变子图或累计保存全部搜索状态。

以下 §1–§9.7 保留早期中间层设计及分阶段实施记录；“当前/尚未接入”均指各节记录时点。
最新公共结构入口、开源内核验证及剩余边界见 §9.8，不将早期协议证明要求施加到结构比较。

## 摘要

- **目标**：在锁定的 JAX/jaxlib 版本上，比较两份 JAX 或 Pallas 程序是否等价。比较依据是程序图、
  执行语义和数学含义，不是数值抽样；不能完成判定时走分类异常，不返回"未知"结果。
- **架构决定**：源语义只适配一次（`ProgramView` 是唯一源事实），`Graph` 由视图派生；图逻辑比较、
  存储/通信分析和数学投影共用同一份事实；只有适配器拥有源格式解释权。**中间层自研**，不把
  JAX/Pallas 直接翻译成 SymPy 作为比较主路径；MLIR 虽然长期有价值，但现阶段接入成本过大，暂不接入。
- **结果决定**：保留"计算图等价 / 数学等价 / 数学不等价 + 异常"契约；新增
  `structural` / `normalized` / `algebraic` 三类等价证据，`normalized` 不是新结果状态。
- **当前最大风险**：同一 mesh 下不同通信协议/路由/拆分合并的等价判定，以及一般整数索引域的
 覆盖与交叠证明；目前只有小规模 CPU tracing 证据。
- **实施顺序**：Pallas 垂直 slice（第 8 节）已建立内部链路；继续补齐 M1，随后推进通信与 JAX 迁移。
