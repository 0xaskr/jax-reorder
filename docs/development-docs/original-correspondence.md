# 原始计算图的对应证据

比较器在规范结构相同时生成 `GraphCorrespondence`，记录输入、常量、方程、结果端口及嵌套区域的双射。随后 `verify_correspondence` 直接读取原始 jaxpr 复核；只有复核通过才返回 `equivalent`。

校验器不执行 BFS，不调用规范化接口，也不读取规范图。它检查全部节点和常量的数量、Primitive 身份、操作数和结果绑定、共享关系、抽象值、参数、子区域、effects 以及隐式有序操作。常量与参数的语义编码仍是共同信任基础；测试因此同时包含独立数值参照和逐字段反例，不能把两段调用相同编码器的代码当成完全独立的证明。

## 同构与重排的论证

对于所有节点均可从有序根回溯到的图，外部输出位置及普通算子的操作数位置是固定标签。从相同的有序根按相同端口顺序 BFS，第一次发现节点时赋号。一个保持这些标签和连接的同构，会在两边产生相同的队列操作；归纳得到相同编号。共享前驱只入队一次，因此共享和重复计算不会混淆。常量同样按首次使用编号，同时保留完整内容和绑定数量。

可执行顺序采用依赖深度与 BFS 编号。每条依赖边的生产者深度严格小于消费者深度，因而重排保持先定义后使用；这一步不交换普通操作数，不应用代数改写。隐式有序操作另有顺序边，并作为额外根。

对于内部区域，允许的接口置换必须同时作用于父节点实参、子区域形参及相应位置元数据。调用结果置换还必须同步父节点结果和子图输出。`jit` 按外部使用路径固定结果位置，再按子图使用位置固定形参；使用路径按到有序根的距离及端口序列确定，不依赖原方程排列。外部函数输入输出始终固定。

独立校验器从原始图检查每一处上述绑定，而不是相信规范化器已经做对。内部图的双射和父节点绑定共同给出递归组合的图同构；控制流还必须保持分支位置及循环角色。孤立部分与对称接口通过[完整图有界搜索](complete-graph.md)建立同样的双射；预算不足或不透明语义仍返回 `unknown`。

单独调用校验器也检查版本、原语支持域和 SSA 定义/使用关系。它不是完整的 JAX 类型检查器；验收仍分别执行 `core.check_jaxpr`、CPU 编译和数值核对。不能给两个相同的非法程序套上恒等对应表后称为已证明可执行。

图同构给出的结论限于相同追踪契约下的计算语义。它不证明任意 Python 行为，不由图差异推出数学不等价，也不承诺跨编译环境的逐位浮点一致。
