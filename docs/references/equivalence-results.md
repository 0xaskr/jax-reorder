# jaxpr 两轮规范化与比较结果

本文记录 `jax-reorder` 的两轮规范化流程、四类比较结果及判定边界，与[架构与比较契约](../../ARCHITECTURE.md)共同约束后续实现。第一轮计算图规范化与比较已实现，接口返回 `equivalent / different / unknown`；第二轮代数模式尚未实现。本文中的四类结果描述完整流程，不把本轮图不匹配直接归为完全不等价。

## 比较范围

比较限定于声明的输入签名、静态参数、执行环境和输入输出 pytree。算子、常量、dtype、shape、primitive 参数及受支持的嵌套计算语义都属于比较依据。

“公式等价”必须说明采用的数值域和适用条件，例如实数运算下的结合律。实数公式等价不代表浮点执行结果相同；不能在判定过程中混用数学公式与浮点执行的语义。

“完全”等措辞仅在声明的比较范围内成立，不表示一般 Python 程序等价，也不提供跨输入签名、跨平台的逐位相等保证。

## 四类结果

| 结果 | 判定含义 |
| --- | --- |
| **完全等价** | 结构规范化后，算子、参数、常量、抽象值、操作数顺序、输入输出及计算依赖一致；受支持的嵌套计算也满足相同要求。 |
| **公式等价，但运算顺序不等价** | 结构未匹配，但通过约定的代数规则确认公式等价；操作数顺序、求值顺序或运算分组不同，浮点结果可能不同。 |
| **完全不等价** | 在约定的语义和输入范围内，有证明或有效反例表明公式不等价。 |
| **无法判定** | 当前规则既不能证明等价，也不能证明不等价，或遇到不支持的情况。 |

“完全不等价”表示两个公式在声明的范围内不是同一个函数，不要求它们在每个输入上都产生不同结果。

## 两轮规范化

### 第一轮：计算图结构重排

第一轮保持计算图的节点语义、依赖关系、操作数位置和运算分组，只消除内部变量编号、独立方程排列等差异。当前采用从输出反向 BFS 的策略：

1. 按函数输出顺序确定遍历起点，按每个节点的操作数顺序回溯依赖，为运算节点生成统一编号。
2. 按依赖深度和 BFS 编号排列节点，保留先定义、后使用的依赖顺序；BFS 访问顺序本身不直接作为方程执行顺序。
3. 精确比较完整结构及其语义信息。第一轮结果相等，归为**完全等价**；不相等时再考虑第二轮。

例如，先计算 `sin(x)` 再计算 `cos(y)`，与交换这两个独立计算的先后顺序、最后仍按相同操作数顺序相加，第一轮应得到相同结果。`a+b` 与 `b+a`、`(a+b)+c` 与 `a+(b+c)` 则改变了操作数位置或连接关系，不由第一轮改写。

比较必须覆盖原始计算图，而不仅是 BFS 编号序列。输出回溯未覆盖的方程也不能忽略；第一版保留并报告这些方程，如果不能完成其结构比较，就不能仅凭输出依赖部分相同宣称完全等价。

### 第二轮：代数规则规范化

第一轮未匹配且显式启用代数模式时，第二轮按照经过审查的规则变换计算图，统一允许改写的操作数顺序、运算分组等代数形式。

例如，在规则允许使用加法交换律和结合律的数值域内，约定 `a`、`b`、`c` 的规范顺序后：

```text
(a + b) + c  → (a + b) + c
(a + c) + b  → (a + b) + c
a + (b + c)  → (a + b) + c
```

目标形式可简写为 `a+b+c`，但实际表示必须明确采用的括号结构。示例中的字母表示已有稳定顺序的操作数，实际规范顺序不能依赖原始变量名称。

第二轮规范化结果相等，且所有改写均满足声明的数值域和适用条件，归为**公式等价，但运算顺序不等价**。这里的运算顺序包括操作数交换、求值顺序或运算分组；第一轮能够消除的独立方程排列差异仍归入完全等价。

代数模式记录所用规则。涉及浮点交换律或结合律时必须发出警告：数学公式等价不保证浮点执行结果相同，也不承诺误差很小。不能把实数域规则直接当作浮点逐位等价规则。

### 第二轮不匹配的含义

第二轮结果不相等，可能是公式不同，也可能是规则不足。例如只支持交换律和结合律、尚未支持分配律时：

```text
a * (b + c)
a * b + a * c
```

两式在实数域中等价，却未必能被当前规则变换成相同形式。支持这些算子，不等于已经支持它们涉及的全部恒等变换。

只有在明确限定的表达式域内，已证明规范化能够终止，并且“公式等价当且仅当规范形式相同”，才能凭第二轮不匹配推出**完全不等价**。当前尚无这样的完备性保证，所以第二轮不匹配默认归为**无法判定**；有符合声明语义的不等价证明或有效反例时，才归为完全不等价。

## 判定流程与证据

1. 核对比较范围与支持条件。不支持的 effects、不透明参数或嵌套构造必须明确报告失败原因，结果归为无法判定；不能通过忽略语义继续匹配。
2. 第一轮进行计算图结构规范化并精确比较。匹配时归为完全等价。
3. 第一轮未匹配且显式启用代数模式时，第二轮按约定规则规范化。规则适用且结果匹配时，归为公式等价，但运算顺序不等价。
4. 若有符合所声明语义的不等价证明或有效反例，归为完全不等价。在已证明规范化完备的限定表达式域内，第二轮不匹配也可作为不等价证据；当前尚未具备此保证。
5. 其余情况归为无法判定，并记录未匹配、规则不足或不支持的具体原因。

结构不一致只能排除第一类，不能直接推出完全不等价。抽样数值一致不能证明等价；浮点结果不同也不能单独证明实数意义下的公式不等价，可能仍属于第二类。证据的语义必须与所报告的结论一致。

上述流程定义两轮的职责与结果含义，具体代数规则集合、适用条件、规范顺序和不等价证据的生成方式仍需分别设计。
