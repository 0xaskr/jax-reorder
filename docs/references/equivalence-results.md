# jaxpr 比较结果分类

本文记录 `jax-reorder` 的四类比较结果及判定边界，与[架构与比较契约](../../ARCHITECTURE.md)共同约束后续实现。当前规范化与比较功能尚未实现，本文描述预期行为。

## 比较范围

比较限定于声明的输入签名、静态参数、执行环境和输入输出 pytree。算子、常量、dtype、shape、primitive 参数及受支持的嵌套计算语义都属于比较依据。

“公式等价”必须说明采用的数值域和适用条件，例如实数运算下的结合律。实数公式等价不代表浮点执行结果相同；不能在判定过程中混用数学公式与浮点执行的语义。

“完全”等措辞仅在声明的比较范围内成立，不表示一般 Python 程序等价，也不提供跨输入签名、跨平台的逐位相等保证。

## 四类结果

| 结果 | 判定含义 |
| --- | --- |
| **完全等价** | 结构规范化后，算子、参数、常量、抽象值、操作数顺序、输入输出及计算依赖一致；受支持的嵌套计算也满足相同要求。 |
| **公式等价，但运算顺序不等价** | 结构未匹配，但通过约定的代数规则确认公式等价；操作数顺序、求值顺序或运算分组不同，浮点结果可能不同。 |
| **完全不等价** | 在约定的语义和输入范围内，有证明或有效反例表明公式不等价。 |
| **无法判定** | 当前规则既不能证明等价，也不能证明不等价，或遇到不支持的情况。 |

“完全不等价”表示两个公式在声明的范围内不是同一个函数，不要求它们在每个输入上都产生不同结果。

## 运算顺序的含义

第一类允许统一内部变量编号，并在保留依赖关系的前提下重排独立算子。例如，先计算 `sin(x)` 再计算 `cos(y)`，与交换这两个独立计算的先后顺序、最后仍按相同操作数顺序相加，归为完全等价。

第二类中的“运算顺序不等价”指操作数交换、运算分组改变等差异，例如：

```text
a + b       ↔ b + a
(a + b) + c ↔ a + (b + c)
```

只有相应代数规则及其适用条件得到确认时，才能归入第二类。代数模式须显式启用，记录所用规则；涉及浮点交换律或结合律时必须发出警告，不承诺误差很小或逐位相等。

## 判定流程与证据

1. 核对比较范围与支持条件。不支持的 effects、不透明参数或嵌套构造必须明确报告失败原因，结果归为无法判定；不能通过忽略语义继续匹配。
2. 进行结构规范化并精确比较。匹配时归为完全等价。
3. 结构未匹配且显式启用代数模式时，尝试约定的代数规则。确认公式等价后归为公式等价，但运算顺序不等价。
4. 若有符合所声明语义的不等价证明或有效反例，归为完全不等价。
5. 其余情况归为无法判定，并记录未匹配、规则不足或不支持的具体原因。

结构不一致只能排除第一类，不能直接推出完全不等价。抽样数值一致不能证明等价；浮点结果不同也不能单独证明实数意义下的公式不等价，可能仍属于第二类。证据的语义必须与所报告的结论一致。

上述分类定义结果含义，具体规范化规则、代数规则集合和不等价证据的生成方式仍需分别设计。
